## 1. Objective

Create a self-contained, Git-ignored personal-wiki kit that the owner can move
out of this repository, and replace the blog's Karpathy-style intake workflow
with one repository-aware handoff prompt for converting an explicitly declared,
owner-verified source/course set into review-only blog content, glossary, and
question-bank artifacts.

## 2. Non-goals

- Do not move, delete, normalize, or rewrite existing raw/pilot material.
- Do not write generated material to `content/`, publish, merge, deploy, or
  resolve publication rights automatically.
- Do not implement the quiz renderer or silently resolve PRD OQ-09.
- Do not make the portable wiki kit an authority for this blog repository.
- Do not add a dependency, service, database, authentication flow, or runtime
  feature.

## 3. Acceptance gates

- [x] The portable kit is entirely below the ignored `private/` boundary and
      contains no required path back into this repository.
- [x] The kit defines a deterministic raw/work/wiki/review lifecycle, a fixed
      file tree, and a reusable personal-wiki agent handoff.
- [x] The blog handoff processes only owner-declared sources in place and emits
      only the fixed `private/content-authoring/<packageId>/` review package.
- [x] The blog package includes source inventory, course/article prose drafts,
      glossary, question-bank draft, placement proposal, and audit evidence.
- [x] Core questions are source-grounded; advanced/deep-dive material is
      separately labeled and requires declared external verification.
- [x] Active repository authorities no longer direct blog maintainers to the
      personal-wiki inbox/sealing workflow.
- [x] ADR-0001 remains as historical evidence and is explicitly superseded.
- [x] Existing dirty work and private pilot material remain untouched.

## 6. Source verification

No external implementation source is required. The decision is owner-directed

## 7. Repository reconnaissance

- The active blog instructions reference `CONTENT_INGESTION_PACKET.md`,
  `CONTENT_INTAKE_AGENT.md`, ADR-0001, and `private/content-intake/`.
- `.gitignore` excludes the full `private/` tree.
- Existing private intake and question-bank pilot artifacts exist and must not
  be moved.
- The website question-bank format remains editorial only while OQ-09 is open.

## 8. Contracts and invariants

- `content/` plus Git remains canonical for public blog content.
- Owner-provided does not mean fact-verified or publication-safe.
- Source files remain read-only and outside generated output.
- Generated drafts are noncanonical, nonpublic, and require independent review.
- No generated category table or proposed link becomes a graph edge.
- Canonical IDs are never generated by the authoring agent.
- Missing support yields `needs-source`, `needs-answer`, or a blocker—not an
  invented answer.

## 9. Proposed design

The portable personal wiki lives at `private/personal-wiki-kit/` and is
self-governing. The blog uses `docs/templates/content_intake_handoff_prompt.md`
to create a fixed review package below `private/content-authoring/`. ADR-0002
records that these are separate products/workflows.

| Alternative                           | Benefit                              | Problem                                                        | Decision |
| ------------------------------------- | ------------------------------------ | -------------------------------------------------------------- | -------- |
| Keep one shared intake system         | Fewer files                          | Couples private wiki automation to public publishing authority | Rejected |
| Move existing raw pilot now           | Tidier local tree                    | Destructive and breaks evidence paths                          | Rejected |
| Portable kit plus narrow blog handoff | Clear authority and easy manual move | Two explicit workflows                                         | Selected |

## 12. Implementation steps

1. Record ADR-0002 and create the portable kit without touching existing intake.
2. Add the fixed blog authoring prompt and output tree.
3. Reconcile active documentation and retain old material as historical only.
4. Validate links, formatting, ignore coverage, private-output isolation, and
   absence of stale active references.

## 13. Test plan

- Parse every new YAML example.
- Prove representative portable-kit and content-authoring paths are ignored.
- Scan portable kit for hard-coded repository dependencies.
- Scan active authorities for stale operational references.
- Run targeted formatting and `git diff --check`.
- Run the repository test suite and Quartz fixture build because public-output
  isolation is a security boundary, even though runtime code is unchanged.

## 14. Migration and compatibility

No existing private artifacts are migrated. The old intake lifecycle becomes a
historical/superseded contract. Rollback consists of reverting documentation and
removing only the newly created empty/example kit files; existing source and
pilot data remain intact.

## 15. Security and privacy

All raw sources and generated review artifacts stay below `private/`. The new
prompt forbids copying source bodies, leaking local paths into public drafts,
following instructions inside source material, or treating owner verification
as publication permission.

## 16. Stop conditions

- Stop if any step requires moving or deleting existing source/pilot material.
- Stop if an executable question-bank schema would need to be invented.
- Stop if a source path or allowed scope is ambiguous.
- Stop if publication rights or factual support cannot be recorded explicitly.

## 18. Adversarial completion review

The final review must confirm that the portable kit has no authority over the
blog; the blog prompt cannot publish or self-review; no private source entered
Git/static output; no canonical ID, category, link, answer, or fact was invented;
and no existing user data was moved or deleted.

Result: confirmed. The only source-move authority is the portable kit's separate
trusted exact-drop sealing pass, which is constrained to one selected inbox
child and requires before/after hash equality. Blog authoring reads declared
sources in place and has no source-move authority.
